Browser Review

Comment on your dev app like in Figma, remove or edit elements, and let Claude Code fix it in the code.

Checking the connection to Claude Code…
Browser Review can't see your pages yet It needs access to websites to show the overlay on your dev app and take screenshots. It only runs where you allow it: see Where it works.

1Connect Claude Code (once)

Run this in a terminal. It adds the Browser Review MCP server to Claude Code for all your projects:


          
        

        

          That's all. You don't start anything yourself: Claude Code starts the MCP server when a session starts, and
          this extension connects to it. The dot above turns green when a Claude Code session is running.
        

        
Needs Node.js 20 or newer (for npx).

        

          Optional: no permission question for every tool. Add this to
          ~/.claude/settings.json:
          

            
{
  "permissions": {
    "allow": ["mcp__browser-review"]
  }
}

            
          

        

      


      

        
2Review your app

        
    
          
  1. Open your dev app: http://localhost or 127.0.0.1 (any port), a dev domain like https://my-app.test (Herd, Valet, DDEV), or any other site you turn on (see Where it works).
    2. 
          
  2. Click the Browser Review icon in the toolbar (pin it via the puzzle icon if you don't see it). The review sidebar opens in the browser's side panel, next to your page.
    3. 
          
  3. 
            Pick element (or hold down Left Alt: the picker starts right away and stops when you let go), click what you want changed, and choose:
            
      
              
    • Comment: write what should change.
      • 
              
    • Remove: the element disappears right away (preview), Claude removes it in the code.
      • 
              
    • Edit: change its texts or add CSS with a live preview, Claude makes the same change.
      • 
            
    
            After sending, the Threads count goes up; tick Open thread in the box to see the new thread in the sidebar instead (it remembers your choice). Need more room to write? Drag the box's bottom-right corner; it remembers the size. The Threads sidebar is the browser's side panel: drag its edge to make it wider. If the Threads button can't open it, use the extension icon or Alt+Shift+T.
          
    4. 
          
  4. Or write a Page comment about the whole page.
    5. 
        

        

          Every comment gets a numbered pin, a screenshot, and the element's selectors, HTML and React component, so
          Claude knows exactly what you mean. What you type survives a reload of your app.

Where it works

        

          By default Browser Review runs by itself on local addresses (localhost, 127.0.0.1,
          [::1]) and dev domains: *.test (Herd, Valet), *.localhost,
          *.local, *.internal, *.ddev.site and *.lndo.site.
        

        

          A dev server on another address, or a staging site? Open it and click the Browser Review icon: it asks nothing
          and turns on for that site (that exact address and port), and stays on there. Nothing runs on sites you did
          not turn on.
        

        

          
          
        

        

          Strict mode keeps it to localhost, 127.0.0.1 and [::1] only: no dev
          domains, and the icon doesn't turn on other sites. Pick it if you'd rather be sure it never runs anywhere else.
        

        
Sites you turned on

    Security
    
        
      
          
    • On a site where it runs, the overlay can read the page (to pick elements, take screenshots and find the React component). That is why it only runs where you allow it.
      • 
          
    • Comments, screenshots and settings stay in this browser. They only go to the Claude Code sessions on this computer, over 127.0.0.1.
      • 
          
    • Turning a site off here stops the overlay from loading there; reload tabs that are open on it. Its comments stay until you delete them.
      • 
        
    
      
    

      
    
        
    Troubleshooting
    
        
    
          The dot stays grey: Claude Code is not connected
          
      
            
    • Did you run the command in step 1? Check with claude mcp list: browser-review should be listed and say Connected.
      • 
            
    • Claude Code only runs the server while a session is open. Start claude, or in a running session type /mcp and reconnect browser-review.
      • 
            
    • Node.js missing or too old: node --version must be 20 or newer.
      • 
            
    • Port 4777 must be free. Another program on that port blocks the connection.
      • 
          
    
          
    Your comments are still saved while the dot is grey. Claude sees them once it connects.
    
        
    
        
    
          Nothing happens when I click the icon
          
      
            
    • On a site that is not on yet, the first click turns it on. In strict mode it only runs on localhost, 127.0.0.1 and [::1]; elsewhere the icon shows a short note. See Where it works.
      • 
            
    • Was the tab open before you installed or reloaded the extension? Reload the page.
      • 
          
    
        
    
        
    
          Claude can't take a screenshot
          
    Claude's capture_screenshot needs the page open in a tab of this browser. It switches to that tab, scrolls to the element and takes the picture.
    
        
    
        
    
          Several Claude Code sessions at once
          
    That works. The first session's server talks to the extension, the others go through it. When the first one closes, another takes over.
    
        
    
        
    
          Where are my comments stored?
          
    In this browser profile, inside the extension (IndexedDB). Nothing leaves your machine: the MCP server only listens on 127.0.0.1. Each browser keeps its own comments: Brave and Firefox don't share them.
    
          
    Removing the extension deletes its comments. Reloading or updating it keeps them.

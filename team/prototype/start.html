A team board in two minutes

Everyone needs Tailscale. The host runs the board in a small Docker container and shares only that container with the team, never their laptop. It works in the same room and across the internet, nobody opens a port, and a wrong setting can't expose anyone's laptop.

  1. 1everyone

    Install Tailscale and Margin Team

    Tailscale with your own free account, and Margin Team from the VS Code Marketplace (or Open VSX in Cursor and Windsurf).

    Already use Tailscale, personally or for work? Keep it as it is. You don't join anyone else's tailnet.

    The host also needs Docker. Teammates don't.

    One extension does everything: it reads git and your terminals, talks to Claude Code and GitHub, and shows the board.

  2. 2host

    Start a team

    Open the repo and run Margin Team: Start a team. Margin starts the board in a small Docker container, margin-team, with Tailscale inside it.

    You reach it at http://localhost:4780. Docker publishes that port on 127.0.0.1 only, so it never appears on the venue Wi-Fi.

    The extension that started the container keeps a host key, so the board knows which requests are yours. Teammates are recognized by Tailscale.

    Connect Claude Code

    The extension offers to add a few Claude Code hooks and the Margin Team MCP server. One click.

    The hooks tell the board what your sessions are doing. The MCP server lets your Claude read the board, so it knows what the others are working on.

    Only the task line, the agent's state and file paths go out. Never your prompts, Claude's answers or terminal output.

  7. 7host

    Local CI first

    The extension reads your GitHub workflow and finds the checks it runs. You confirm them once, and they're saved in margin-team.json in the repo, so the whole team uses the same ones.

    From then on every push runs those checks on your own laptop first. When Claude runs git push and a check fails, the push waits and Claude gets the failure to fix. Your own pushes get the same check through a git pre-push hook.

    GitHub CI becomes the confirmation, not the place you find out. At a hackathon, where the Actions queue is slow and every red PR costs minutes, that matters.

    ⓘFound 3 checks in .github/workflows/ci.yml. Run them before every push?
    Source: Margin Team
    Edit checksUse these
    // margin-team.json, committed so the team shares it
{
  "localCI": {
    "checks": ["pnpm typecheck", "pnpm test", "pnpm build"],
    "beforePush": "hold"   // "hold" the push, or only "warn"
  }
}

The network

Everyone stays in their own tailnet. The only thing shared is the board's container. Andor reaches it on localhost, the teammates through Tailscale.

Traffic between laptops is WireGuard, encrypted end to end, direct when possible. GitHub isn't in this picture: each laptop reads PRs and CI with its own login.

Teammates can reach

  • The board in the container, over HTTPS on port 4780
  • Nothing else: the container is all they're shared

Nobody can reach

  • Andor's laptop: its dev server, Docker ports and SSH
  • Andor's other devices: they're not shared
  • Andor's tailnet from inside the container: no proxy, so no way out
  • Teammates' laptops: a shared machine can't start connections
  • Anything from the internet or the venue Wi-Fi

Does this change my existing Tailscale?

Teammates: no

Your tailnet stays yours

You don't join the host's tailnet. Accepting the share adds one machine, Andor's laptop, to your own tailnet. Your devices stay invisible to Andor, and you keep your work or personal tailnet connected the whole time.

Host: one extra machine

No policy changes

The container shows up as one more machine in your tailnet, margin-andor. Nothing on your laptop and nothing in your policy changes.

Get a setting wrong, or forget one, and the worst case is that the board doesn't work. Your laptop is never part of the share.

Company tailnets: ask first

Admins decide

On a company tailnet, admins may not allow accepting shares, and as host you may not be allowed to edit the policy. Then host from a personal account, or join with a personal laptop.

Two rules that don't depend on the network. Board text is untrusted input for everyone's Claude: it arrives as marked data with short fields. And nothing from the network is ever run: local CI checks come only from margin-team.json in git.

After the hackathon

End the team

The host runs Margin Team: End team. The container stops, every laptop deletes the board, and Margin reminds the host to stop sharing margin-andor. Forget Margin machine also removes it from the tailnet.

Leave a team

Anyone can run Margin Team: Leave team, and the host can remove someone. Your cards stay and your agents stop reporting. Remove margin-andor from your tailnet whenever you like.

Remove the hooks

The hooks do nothing outside a team. Margin Team: Disconnect Claude Code takes them out again.

Not using VS Code? With Tailscale running, npx margin-team join margin-andor adds the Claude Code hooks and the MCP server. Your sessions and branches still show up; you just see the board in the browser, and there's no terminal info.
